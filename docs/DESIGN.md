# Deep Dish — дизайн-концепция

> Канон визуального языка приложения. Обновляется при изменении стиля, не при каждой фиче.
> История решений — PLAN.md (v5–v30); здесь — как оно устроено сейчас и почему.

## Принципы

1. **Воздушность** — пространство вместо линий: разделение отступами, не рамками; карточки без обводок.
2. **Стекло и градиенты** — полупрозрачные карточки с размытием поверх радиальных градиентов (пресеты по углам, интенсивность ×1); акценты — градиент от основного тона к светлому.
3. **Кольцо — фирменный мотив** (иконка И4, кольцо калорий, кольцо цели, мини-кольца): прогресс всегда круглый.
4. **Без кнопочности** — действия выглядят как ссылки/строки, кроме главного действия экрана (одна акцентная кнопка).
5. **Сдержанные эмодзи** — максимум один на блок; в баннерах обязательны, в остальном — по необходимости.

## Компоненты

### Кольца
- **Кольцо калорий** (96px, штрих 10): остаток дня; тап переключает в сегментированный вид Б/Ж/У — три дуги оттенками одного цвета (насыщенность 1 / 0.62 / 0.36), размер не меняется.
- **Кольцо цели** (тот же размер): прогресс = тренд/план, без обрезки; ≥190% показывает «×2», ≥290% — «×N»; заполнение капается на 100%, светофор <50 warn / <80 acc / ≥80 ok. При «держать»/без цели — скрыто.
- **Мини-кольцо** в списке (46px) — точечные индикаторы.

### Панель итога («Сегодня»)
Три равные колонки: кольцо слева (центр над панелью белков), текст по центру («1 704 / из 2 060 · 83%» — без «ккал»), кольцо цели справа (центр над панелью углеводов).

### Шиты (bottom sheets)
Скругление 30px сверху, плотный фон `--panel`; закрытие — свайп вниз за шапку (ручка + заголовок, порог 70px или флик) или тап по затемнению. Кнопка ✕ не используется.

### Баннеры (top sheets)
Плашка сверху с градиентной кромкой слева (warn — тёплой); закрытие крестиком; авто-скрытие после 3 действий с едой; раз в день каждый.

### Кнопки
- `dd-action` — главное действие: градиентная заливка акцентом, текст цвета акцента; `strong` — ярче.
- Опасное действие — текст цвета `--warn` (не красная заливка), кроме явных подтверждений.
- **Sticky-сохранение**: на экранах с правками (Профиль) при несохранённых изменениях кнопка «Сохранить изменения» всплывает фиксированно над таб-баром — правка всегда завершается в поле зрения. Принять как стандарт для экранов-форм.

### Таб-бар
4 вкладки (Сегодня, Профиль, Семья, Настройки), монохромные SVG-иконки единого стиля (линия 2px, currentColor), подписи под иконкой; панель непрозрачная, автоскрытие при скролле.

### Шапка «Сегодня»
Блок ‹дата› слева (стрелки массивные, без панелей), лого с кольцом справа; «deep dish» кеглем даты.

## Правила

- **Равные кнопки** в группе — одинаковая ширина (flex: 1): приёмы в карточке ввода, режимы цели, темпы.
- **Оттенки одного цвета** вместо радуги: сегменты БЖУ, состояния.
- Радиальные градиенты — пресетом по экрану, кросс-фейд ~300мс при переходах.
- Тёмная тема: поля — плотный непрозрачный `--panel` + явный `-webkit-text-fill-color` (полупрозрачность ломает нативные контролы iOS).
- Числа — табличные цифры (`dd-num`), тысячи с пробелом, десятичная — запятая.

## Палитры

5 гамм × light/dark, токены: `bg/bg2/bg3/panel/glass/glassStrong/tx/mut/acc/acc2/accFg/veil/tr/ok/warn`.
Семантика: `ok` — позитив, `warn` — тревога/опасность, `acc` — нейтральный акцент. Светофор цели: warn <50%, acc 50–80%, ok ≥80%.


## Канон разделов и контролов (v0.7.0, по фидбеку В.)

### Раздел = карточка с заголовком внутри
Любой смысловый раздел экрана — `dd-card` с подписью `dd-field-label` **внутри** карточки, сверху (не над карточкой). Так оформлен Профиль; с v0.7.0 Настройки приведены к тому же правилу. Несколько независимых настроек одного раздела — одна карточка, подписи между блоками.

### Сегментные группы — равными долями
`dd-seg` (выбор из 2–5 коротких взаимоисключающих вариантов: тема, размер текста, распределение БЖУ, пол, темп, цель): кнопки делят ширину контейнера поровну (`flex: 1 1 0` в CSS — глобально). Перенос на вторую строку допустим только при невозможности вместить (крупный текст). Варианты с длинными именами (одно слово шире равной доли — например, палитры «Брусника») в сегмент не идут: для них — список строк со свотчем/значением справа (аудит v0.7.0).

### Строки-настройки
Пара «подпись + значение/действие» — `Row`: слева подпись (и серая подсказка 0.6875rem под ней), справа действие-ссылка. Высота строк в списках внутри раздела — одинаковая (min-height), включая строки без поля ввода.

### Иерархия чисел записи (Сегодня)
Имя приёма 0.9375rem/600 = итог приёма 0.9375rem/700 > калораж продукта 0.90625rem/400 > имя продукта 0.84375rem/400 (мутный). В строке: имя обрезается «…» в собственном спане; граммовка/шт и калораж — `flex-none`, всегда видимы.

### Компакт-режим (крупный текст)
- Кольца и чипы БЖУ — только числа; чипы с буквой («Б 80 г»).
- Сегментные ряды, не влезающие по ширине, заменяются одной активной кнопкой (пример: Активность).

## Канон v2 (v0.7.3, по фидбеку В. 24.10)

### Заголовки блоков — один уровень
Заголовок раздела внутри карточки — всегда `dd-field-label` (0.6875rem, мутный, сверху карточки). Допустим второй уровень для визуального выделения имени сервиса/фичи в сложных блоках Семьи («Витрина метрик», «Мост Apple Health») — `text-sm font-semibold`, но только один на блок и только там, где блок сам по себе «мини-экран». Смешивать в одном блоке нельзя.

### Выпадающие списки вместо длинных списков выбора
Если вариантов выбора больше трёх и все они не помещаются в сегмент (палитры, будущие списки) — свёрнутая строка-кнопка со значением и свотчем/стрелкой справа + доппанель сверху (TopSheet) со списком строк. Отступы строк списка — как у сегментных кнопок (13px от краёв), min-height 46, выбранная строка подсвечена `--veil`.

### Удаление элемента списка — свайп влево
Удаление строки списка — свайп строки влево (SwipeRow) с красной подложкой «удалить» + подтверждение для разрушительного. Кнопка «⋯» — только свойства/редактирование, не удаление. Текущее соответствие: ингредиенты рецепта ✓, сохранённые приёмы ✓ (v0.7.3, было «⋯»), записи — удаление из карточки записи. Новые списки добавлять только по этому правилу.

### Обязательные поля — графически
Обязательность поля помечается в лейбле (« · обязательные»); после попытки сохранения незаполненные поля подсвечиваются цветом `--warn` (лейбл + бордер + «!»). Подсказки-предложения «заполни…» как способ указать обязательность не используются. Кнопка «Сохранить» не блокируется: клик по невалидной форме подсвечивает, что не заполнено.

### Онлайн-данные визуально отделены
Строки из интернета (Open Food Facts) идут под локальной выдачей с заголовком секции «Из интернета · Open Food Facts» — источник всегда ясен. Онлайн-секции не открываются без интернета и не показывают ошибок в лоб: офлайн-состояния описываются спокойным текстом с причиной («вне домашней сети») и кнопкой «повторить».

### Служебные категории не существуют
Категории-суррогаты импорта («Импорт OFF», «Импорт MFP») недоступны пользователю ни в выборе категории, ни в красных флагах. Всё импортируемое категоризуется словарём по названию; не угадалось — «Прочее».

### Подсказки в полях ввода
Placeholder заметно бледнее значения (подмешивание фона), создавая ощущение незаполненности. Внутри placeholder живут примеры («напр. Простоквашино»), пояснения-инструкции в placeholder не живут.

## Канон v3 (v0.7.8, аудит после «последние правки разъехались»)

### Плотность и воздух
Вертикальные зазоры внутри закреплённых зон: блоки AlwaysOn (кольца → чипы → кнопка) разделяются `mb-3`, не `mb-2` — зона видна целиком дольше секунды, воздух важнее экономии 8px. Внутри карточек — наоборот, плотно: строки списков 44–54px, подсказки 0.625–0.6875rem мутным.

### Пустые состояния
Один ритм: текст-пояснение (mt-3) → кнопки-действия (mt-3) — зазор текст→кнопки равен зазору выдача→текст. Кнопка создания называет запрос: «＋ {запрос}», без слова «Создать».

### Индикаторы макро
Точка макро всегда цветная и всегда рядом со словом при первой встрече в контексте (легенда: «● жиры»), далее — только точка у строки. Никогда две точки подряд.

### Поля в шитах
Поля ввода внутри шитов не обрезают кнопку действия: кнопка длинных подписей («Сохранить приём пищи») идёт полной шириной под полем, не рядом.
