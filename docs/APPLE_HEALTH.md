# Мост Apple Health

На QNAP сверена версия 0.4.7. Контракт, подготовленный для 0.4.8, входит в кандидат 0.4.9 и проверен на синтетической базе. Подписанная «Быстрая команда», чтение веса и запись калорий в «Здоровье» проходят отдельную приёмку на Apple-устройствах.

## Что делает сервер 0.4.9

- `POST /health/weight` принимает один JSON-объект или массив. Новый клиент передаёт код в заголовке `X-DeepDish-Health-Code`. Для ранее настроенных команд сохраняется `?code=…`.
- `date` — локальный календарный день на iPhone (`yyyy-MM-dd`). `kg` — число в килограммах. `measuredAt` — момент измерения ISO 8601 со смещением часового пояса. Из нескольких замеров одной даты сохраняется самый свежий. Повтор того же измерения не меняет запись. Старые команды без времени измерения сохраняют прежний порядок обновления до первого образца с временем.
- Сервер сохраняет одно актуальное импортированное измерение на дату. Замена более ранней ручной записи доезжает через обычный обмен. При повторном импорте затронутой даты переиздаётся и отметка удаления, оставленная сервером 0.4.7.
- `GET /health/day?date=YYYY-MM-DD` возвращает `date` и округлённые `kcal` из уже синхронизированных записей NAS. Для команды указывайте локальную дату явно. Ответ открывается по коду участника и помечен `Cache-Control: no-store`.
- Страница `/health/setup` показывает адреса без кодов. Личные параметры задаются на iPhone при установке. Исходный файл команды для подписи и передачи должен содержать только вопросы при импорте, без домашнего адреса и действующего кода.

## Часть для Apple-устройств

1. **Импорт веса.** Команда считывает последние образцы «Масса тела» в порядке от новых к старым, берёт числовое значение в килограммах и отправляет образцы в API со временем и локальным днём. Использует два параметра при импорте: HTTPS-адрес NAS и код моста. После установки кнопка запуска показывает технический результат.
2. **Проверка суммы.** Отдельный шаг считывает итог за выбранную дату с NAS. Сначала сравниваются показание в PWA, ответ API и результат на iPhone. Если дневник ещё не синхронизирован, этот итог предварительный.
3. **Запись пищевой энергии.** Принимается отдельно. Условие выпуска — повторный запуск не удваивает итог, а поздняя правка обновляет только запись Deep Dish. Нужно проверить, позволяет ли установленное действие «Записать данные „Здоровья“» присвоить устойчивый идентификатор и обновить собственную запись. HealthKit поддерживает `HKMetadataKeySyncIdentifier` и `HKMetadataKeySyncVersion`, но соответствие действий Shortcuts этому контракту предстоит проверить на устройстве. До этого используется чтение суммы и ручная проверка.
4. **Доставка.** Собрать команду на Apple-устройстве и передать семье подписанный файл или приглашение iCloud. Подтверждение прав на чтение массы и запись пищевой энергии выполняется в системном интерфейсе на iPhone. Автоматизацию по времени подключить после успешного прогона повторов.

## Приёмка

| Проверка | Статус |
|---|---|
| Пачка JSON и один объект через HTTP | Пройдена локально |
| Сброс кода, отказ с неверным кодом, старый параметр URL | Пройдена локально |
| Повтор измерения, более старый замер, образец около полуночи | Пройдена локально |
| Замена ручного веса, переиздание старой отметки и доставка через `/sync` | Пройдена локально |
| Сумма за явный день, поздняя правка в дневнике и неверная календарная дата | Пройдена локально |
| Импорт подписанного файла, разрешение, реальные единицы и локальная дата на iPhone | Требуется Apple-устройство |
| Два повторных запуска, поздняя правка, запрет фонового скачка калорий | Требуется Apple-устройство |
| TLS и связь с NAS после развёртывания 0.4.9 | Требуется приёмка при выпуске |

Для разработчика: [локальный запуск API](../backend/README.md#локальная-разработка), затем `python tools/health_smoke.py http://127.0.0.1:8689` на свежей тестовой БД.
