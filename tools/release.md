# Чек-лист релиза Deep Dish

Общие сценарии приведены в [USER_SCENARIOS.md](../docs/USER_SCENARIOS.md). Результат проверки фиксируется с версией клиента, сервера и SHA. [GitHub Actions](../.github/workflows/deploy.yml) запускает клиентские и серверные тесты, собирает клиент, проверяет API Apple Health на синтетической SQLite, офлайн-сценарий в Chromium и мобильную вёрстку в WebKit. Приёмка iPhone и NAS проводится отдельно.

1. На чистом клоне выполнить `npm ci`, `npm test`, `npm run build` и `python -m unittest discover -s backend -p "test_*.py"`. Для Python установить зависимости из `backend/requirements.txt`. Проверить предупреждения сборки.
2. Для автоматической проверки сборки выполнить `npx playwright-core install --only-shell chromium webkit`, `npm run test:browser` и `npm run test:mobile`. Офлайн-сценарий поднимает preview и API с временной SQLite, включает service worker и проверяет доставку ровно одной записи после восстановления сети. Мобильный прогон проверяет экраны и модальные панели с безопасными полями и эмуляцией клавиатуры. Для ручного прогона запустить `npm run preview -- --host 127.0.0.1 --port 4175` и отдельный тестовый API по [локальной инструкции](../backend/README.md#локальная-разработка).
3. Проверить ежедневный путь вручную в браузере: открытие, поиск недавнего продукта, добавление и правка, светлая и тёмная темы. Для проверки офлайна использовать отдельный профиль с включённым service worker. Пройти затронутые сценарии на iPhone, указать фактические условия и результаты.
4. При изменении обмена проверить двух участников, задержку/повтор ответа, длинный офлайн и большие порции данных на вымышленном дневнике. При изменении схемы испытать обновление с предыдущей версии и возврат к ней. При изменении моста выполнить `python tools/health_smoke.py http://127.0.0.1:8689` на пустой тестовой БД и [приёмку на iPhone](../docs/APPLE_HEALTH.md#приёмка).
5. При изменении сервера сверить пути монтирования и сделать проверенную копию. При миграции схемы сначала восстановить отдельный экземпляр из резервного носителя. После развёртывания проверить версию в `/openapi.json`, `/healthz`, `/backup-healthz` по доверенному HTTPS. [Порядок для текущей миграции](../backend/README.md#обновление-с-047-до-049)
6. Обновить версии и документацию. После публикации сверить сборку на GitHub Pages с ожидаемыми версией и SHA, проверить поведение установленной PWA с новым service worker. В приватной диагностике, если она доступна, посмотреть отказы и незавершённые обмены. Значения токенов в вывод и Git не включать.
7. Обновить [план](../PLAN.md), [спецификацию](../SPEC.md), README и затронутые сценарии. `python tools/sync_docs.py` генерирует заметку «Состояние Deep Dish». Feedback отражает пользовательские сообщения по версии.

Сценарии, где необходимы iPhone, NAS или разрешения Apple Health, считаются проверенными после прогона на соответствующем устройстве.
