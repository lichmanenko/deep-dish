# Deep Dish — план разработки (v3)

**Имя приложения:** Deep Dish (решение В. 03.10.2026; прежде — «КалорийОК»). Репо переименован: `lichmanenko/calorieok` → `lichmanenko/deep-dish` (GitHub делает редиректы со старого имени; установленная на телефоне PWA v2 после rename не переживает обновления — принято, совместимость не нужна).

**Статус:** план v4, все вопросы В. закрыты (03.10.2026). Архитектура — в `SPEC.md`. Следующий шаг: старт M0 по команде В.

## Цель

Домашний трекер питания и веса для семьи В. под iPhone: быстрый ввод еды, составные блюда, честная динамика веса, адаптивная норма калорий, общий семейный каталог продуктов/блюд. Пет-проект, бюджет 0 ₽, вне корпоративной отчётности (решение В. 03.10). Итеративная разработка с помощью агентов.

## Что умеет v2 и что берём (инвентарь из бандла, 03.10)

v2 — дневник по дням, 4 слота приёмов пищи, 140 продуктов + одиночные «свои», норма по Миффлину с фиксированным дефицитом −400/+300, график 7 дней, экспорт XLSX (30 дней), удаление записей, PWA-офлайн. Не берём ничего, кроме базы продуктов и общей идеи PWA-дневника.

## Платформенные рамки (проверено 03.10)

- Home Screen PWA на iOS: standalone, долгоживущее хранилище (home-screen приложения исключены из 7-дневного ITP-лимита, WebKit blog 10218), push не нужен.
- HealthKit из веба недоступен. Мост — «Быстрые команды»: действие «Log Health Sample» пишет в Health и вес (Body Mass), и калории (Dietary Energy) — подтверждено 03.10. Схема: shortcut → GET/POST наш API на NAS → Health и обратно. Настройка один раз на iPhone.
- BarcodeDetector в iOS Safari нет (проверено 03.10). Сканер камерой возможен только JS-библиотекой (ZXing/html5-qrcode) — качество среднее; стартуем с поиска по названию и ручного ввода EAN, сканер — эксперимент в M3.
- Background sync нет; синк — при открытии приложения и по кнопке.
- Электроперебои на NAS: SQLite в WAL-режиме переживает внезапное отключение; контейнер с автостартом; бэкапы HBS3.

## Алгоритм нормы

MFP считает BMR той же формулой Миффлина–Сан Жеора — «точность» MFP в базе и привычке, не в формуле. Deep Dish — адаптивная норма (подход MacroFactor/Carbon):
1. Старт: Миффлин / Кэтч–МакАрдл (при известном % жира) / ручной TDEE + цель и темп (кг/нед).
2. После ≥2 недель данных: TDEE_факт ≈ среднее потребление за 14 дней + 7700 × (−тренд веса кг/день); тренд веса — регрессия за 14 дней (не сырые взвешивания).
3. Цель = TDEE_факт ± дефицит/профицит по темпу; ограничители: изменение цели ≤150 ккал/нед, пол не ниже 1,1×BMR.
4. Экран «почему такая цифра» — обязателен (доверие к приложению).

## Решения В. (03–04.10.2026)

1. Сеть: **Headscale сразу** (свой координационный сервер контейнером на NAS, без лимита пользователей; цена — разовая установка CA-профиля Caddy на каждое устройство семьи).
2. Дневники **приватны per-user**; общее — только каталог продуктов/блюд.
3. В записях фиксируются **оба времени**: приёма пищи и создания записи.
4. Приёмы пищи — **расширяемые слоты** (дефолт: завтрак/обед/ужин/перекус).
5. Apple Health, однонаправленно: **вес читаем из Health** в приложение, **калории пишем в Health** из приложения. Не обязательны, можно догнать позже (M3).
6. MyFitnessPal: **миграцию исключаем** (В.: «нет чего-то очень важного, чтобы тратить время»). Свои продукты заведутся через OFF и вручную.
7. Репо `deep-dish` — **публичный** (бесплатный Pages).
8. Блюда — **модель MyFitnessPal**: продукты + рецепты (составные, с выходом) + сохранённые приёмы пищи (one-tap) + недавние/частые/избранное. Детали — `SPEC.md`.
9. v2 на телефоне В. уже удалена; **файлы v2-деплоя сносим при старте M0** (заменяются новым приложением).
10. **Гамма «Графит·сталь» (№7), иконка И4 «Кольцо нормы»** (В., 04.10). Кольцо — фирменный мотив: иконка, кольцо калорий, прогресс нормы/цели — один визуальный язык. Токены — SPEC §8.
11. **Онбординг с постановкой целей; цель опциональна** (В., 04.10): без профиля — просто дневник; с профилем без цели — норма; с целью — норма + динамика + баннеры.
12. **Время приёмов пищи**: дефолтные времена завтрака/обеда/ужина в настройках (в слот пишется автоматически); время спрашивается только для перекуса; время внесения записи — служебное, в интерфейсе не показывается (В., 04.10).
13. **Мотивационные баннеры — элемент дизайна приложения, НЕ пуши** (В., 04.10, ответами закрыты все уточнения): выезжающая панель сверху, видна на всех экранах, пока не закрыта; может сама исчезать после нескольких действий пользователя; часовая зона — устройства; тональность: 3 дерзких + 2 нейтральных текста; оба типа отключаемы в настройках.
14. **Окно срывов — по категориям угощения, а не по превышению нормы** (В., 04.10): триггер — историческая связка «время × категория из красных флагов» (Сладкое/Фастфуд/Снеки/Алкоголь + свои категории), даже если дневная норма не превышена. Пример В.: полбутылки вина в 10:00 каждый день — превышения может не быть, паттерн — налицо.
15. **Категоризация продуктов — трёхэшелонная** (агент, 04.10): (1) категория обязательна при создании продукта/рецепта + автоматически из Open Food Facts при импорте (маппинг их категорий на наши); (2) офлайн keyword-правила по названию для «без категории»; (3) ML-классификация на NAS для накопленного «без категории» (второй эшелон, Coral TPU не обязателен для этой задачи — инференс крошечный; Coral пригодится позже для распознавания еды по фото).
16. **Эмодзи — сдержанно, выборочно** (В., 04.10): не больше одного на блок, только где помогает сканированию; обязательны в баннерах.
17. **Экран добавления еды** (В., 04.10): поле поиска → «Недавние» → «Проверенные ⭐» → «Каталог» (по категориям); все секции сворачиваемые. «Проверенное ⭐» — одна пометка на две роли: быстрый доступ + личный сертификат доверия к КБЖУ (объединение «избранного» и «подтверждённого», решение агента, подтверждается вёрсткой).
18. **Гаммы в настройках** (В., 04.10): выбор акцентной гаммы на устройстве — Графит·сталь (дефолт) + Лазурь + Индиго + Брусника + Матча; иконка приложения всегда графитовая (единый бренд); светлая/тёмная тема — как сейчас, автоматически + ручной тумблер.
19. **Проверка КБЖУ при вводе** (В., 04.10): офлайн-эвристика энергетического баланса (4/4/9, алкоголь — особый случай) всегда; при онлайне — сверка с Open Food Facts по похожему названию; расхождение ~±25% → popup при сохранении («сохранить как есть / исправить») + постоянная пометка ⚠️ у карточки в списках. Отдельный баннер не нужен — popup в моменте + пометка достаточно (рекомендация агента).
20. **Фото-распознавание еды — не делаем; Coral TPU — учитываем как доступный ресурс NAS** (В., 04.10, уточнение: не исключать из поля зрения, для фото-анализа блюд он не нужен; пригоден для будущих ML-задач на сервере).
21. **Функциональное офлайн-тестирование — обязанность агента** (В., 04.10): при каждом релизе M0+ протокол «авиарежим → холодный запуск → полный функционал» (ввод/правка/удаление/копирование дня/поиск/экспорт).
22. **Документ функциональности в Obsidian** (В., 04.10): «LichVault/Личное/Deep Dish/Функциональность Deep Dish.md» — подробное пользовательское описание всего, что умеет приложение (со статусами по итерациям); агент обязан актуализировать его при каждом изменении функциональности.

Челлендж-режим — отложен на будущее. Уведомление о получении — top-sheet, авто-скрытие через 3 действия. Реализация M3.

Таблица в SPEC §9.
27. **Вес: основной путь — умные весы → Apple Health → приложение** (В., 05.10: ручной ввод «лишний»). Ручной ввод остаётся временным fallback до Health-моста (M3) — без него невозможна адаптивная норма M1; после моста — прячется.
28. **Баннер «окно срыва» показывается с упреждением ~1 час до начала окна** и до его конца (В., 05.10: «пользователь может не зайти в окно — он в это время ест»).
29. **MyFitnessPal-импорт возвращён как опция** (В., 05.10): 7-дневный Premium-триал даёт полный CSV-экспорт; если В. оформит и выгрузит — пишем парсер (M3). Биллинг и отмена подписки — на В.
30. **LLM-анализ периодов** (В., 05.10): регулярная выгрузка данных за период и разбор агентом (динамика, ретроспектива на всю глубину) — M3+ поверх метрик и NAS-данных; в приложение LLM не встраивается.
31. **Роли: единое приложение у всех; роль admin на сервере — у В.** (В., 05.10): управление пользователями/токенами + семейная витрина метрик; у членов семьи — свои метрики и дневник.
32. **Онбординг включает все манипуляции с телефоном** (В., 05.10): блок «настройка устройства» — «На экран Домой» (M0), CA-профиль и подключение к серверу (M2), Health-команды (M3) — пошагово, с галочками выполнения.
33. **Время еды — атрибут каждой записи** (В., 05.10, ревизия решения 12): у каждой записи своё время; слоты остаются группировкой, не контейнером одного времени. Автоподстановка ускоряет ввод: завтрак/обед/ужин — дефолт слота из настроек, перекус — текущее время; время видно и правится в карточке записи рядом с граммами. Снимает «одно время на перекус»; заодно даёт паттерну срывов точные времена (3–7 перекусов в день — все разные).
34. **Персданные на сервере (NAS) — принцип идентифицируемости** (В., 05.10, ревизия): в базе нет НИЧЕГО идентифицирующего личность — имён, email, телефонов. Юзер = id + псевдоним + токен. **Биометрия профиля (пол/возраст/рост/цель) — синкается на сервер** (ревизия по замечанию В.: без неё невозможен полноценный анализ — BMR, безопасные границы нормы, референсы темпа, метаболическая интерпретация); данные при этом остаются псевдонимизированными. Норма-история — тоже на сервере.
35. **MFP-переход — после M2** (В., 05.10, ревизия): до импорта В. ведёт основной учёт в MFP, в DD — только тестовые записи; после M2 и импорта переключается на DD как основной инструмент. Сценарий перехода: агент даёт команду-инструкцию на триал (оплата — турецкий Apple ID) → В. выгружает CSV → парсер импортирует историю → тестовые записи DD до даты импорта удаляются (функция «очистить дневник до даты», с подтверждением).
36.5. **Радиальные градиенты — уровень ×1** (В., 05.10): два стальных пятна по углам поверх линейного перелива, пресеты позиций по экранам, кросс-фейд при переходах; одинаково в светлой и тёмной теме.
36.55. **Мини-сводка дней на «Сегодня» — отклонена В.** (05.10, «не нужна»); вместо неё динамика появится в M1 в составе графиков.
36.56. **Бесшовные обновления PWA** (В., 05.10): данные в IndexedDB переживают обновления кода; SW качает новую версию в фоне при выходе в сеть (проверка на событии online + раз в час + при каждом холодном старте); пользователю — тост «Доступна новая версия — Обновить» (v0.1.2); каждое событие метрик несёт версию приложения; серверная видимость «кто на какой версии» — M2 через метрики app_open. Переустановка PWA не требуется никогда.
36.57. **Экранная фактура (iPhone, iOS 26/27)** (В., 05.10): целевые экраны — iPhone 17/17 Pro 402×874 pt (safe top 62 — Dynamic Island, bottom 34), Pro Max 440×956, Air 420×912 (top 68), старшие модели 393×852; правило: все основные экраны (Сегодня, Профиль, Настройки, Онбординг, карточка ввода) работают БЕЗ скролла на 393×852 с учётом инсетов; скролл — только внутренним контентным блокам; компоновка 100dvh + env(safe-area-inset-*) (вёрстка — v0.1.3).
36.6. **Отображение времени записей** (В., 05.10): в списках время показывается только у перекусов (дефолт); настройка «показывать время: только перекусы / все записи». Время хранится у каждой записи независимо от отображения (нужно паттерну срывов).
36. **Функция «очистить дневник до даты X»** — в настройках (блок импорта/данных): с подтверждением и предварительным экспортом; используется при переходе с MFP и вообще при чистке тестовых данных.

## Архитектура (0 ₽)

Полная спецификация — `SPEC.md`. Кратко:
- PWA (React+TS+Vite+Tailwind+Dexie) на GitHub Pages; offline-first: сервер — невидимый слой синхронизации, первый запуск без сервера.
- Бэкенд (M2): NAS TS-264C, контейнеры: API (FastAPI+SQLite WAL), Caddy (HTTPS, внутренний CA), Headscale, tailscaled. Доступ — только из частной сети; бэкапы HBS3.
- Синк: uuid + updatedAt + tombstone, last-write-wins; дневники приватные, каталог общий, чужое редактируется через fork.
- Внешняя база: Open Food Facts — ленивый онлайн-поиск по EAN/названию + «сохранить в каталог».
- Health-мост (M3): Shortcuts поверх NAS-API (вес: Health→приложение; калории: приложение→Health).

## План итераций

- **M0 — ядро (полностью офлайн):** дизайн-токены «Графит·сталь» с радиальными градиентами (уровень — на выборе В. из 0/×1/×2), иконка И4 (готова); онбординг (приветствие → как вносить → профиль/цель опц. → «На экран Домой» с галочкой); Dexie-схема, каталог (база v2 + свои + рецепты + сохранённые приёмы), экран ввода (поиск → «Недавние» → «Проверенные ⭐» → «Каталог», всё сворачиваемое; «+» с правкой порции и времени в одной карточке); «Сегодня» с датами-свайпами/стрелками/календарём, время у каждой записи; проверка КБЖУ (эвристика + popup); гаммы в настройках; экспорт JSON/CSV; локальный журнал продуктовых событий. Деплой Pages, установка, офлайн-приёмка (агент, протокол).
- **M1 — вес и умная норма:** ручной ввод веса (временно), цель и темп, графики с трендом, прогноз, адаптивная норма + экран «почему»; мотивационные top-sheet-баннеры (тип А утром; тип Б с упреждением 1 час до окна срывов; тексты 3+2, тумблеры, авто-скрытие); красные флаги (категории).
